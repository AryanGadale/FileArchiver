File compression is an important technique used in computer science and information technology to reduce the amount of storage space required to store data. Compression works by representing information in a more efficient form while preserving the original information when lossless compression is used. One of the well known lossless compression techniques is Huffman coding. Huffman coding is based on the idea that frequently occurring characters should be represented using shorter binary codes, while characters that occur less frequently can be represented using longer binary codes. This makes the overall representation smaller than the original representation in many types of files.

In our File Archiver and Compressor project, we use Huffman coding to demonstrate how data structures and algorithms can be combined to solve a practical problem. The program first reads the input file and analyzes the frequency of every character present in the file. The frequency information is stored so that the program knows which characters occur frequently and which characters occur rarely. After the frequency analysis is completed, a Huffman node is created for every unique character. Each node stores the character, its frequency, and pointers to its left and right child nodes.

The next important step is the construction of the Huffman tree. A minimum priority queue is used to efficiently find the two nodes having the smallest frequencies. These two nodes are removed from the priority queue and combined into a new internal node whose frequency is equal to the sum of the frequencies of the two selected nodes. The new node is then inserted back into the priority queue. This process is repeated until only one node remains. The remaining node becomes the root of the Huffman binary tree.

After the Huffman tree has been constructed, the program generates binary codes for every character. While traversing the tree, moving to the left child represents a zero and moving to the right child represents a one. When a leaf node is reached, the sequence of zeros and ones collected during the traversal becomes the Huffman code for that character. Characters with higher frequencies generally receive shorter codes, while characters with lower frequencies generally receive longer codes. These codes are then used to transform the original file into a compressed sequence of bits.

The compressed bits cannot simply be stored as individual characters because doing so would require unnecessary space. Therefore, the program packs groups of eight bits into a single byte. The resulting bytes are stored inside a custom Huffman archive with the extension .huff. The archive also stores information required for extraction, including the original file size, the number of unique symbols, the frequency of each symbol, and the number of valid encoded bits. This information allows the program to reconstruct the same Huffman tree when the archive is extracted.

During extraction, the program first checks the archive identifier to make sure that the file is a valid Huffman archive. It then reads the stored frequency information and reconstructs the Huffman tree using the same minimum priority queue process used during compression. After the tree has been reconstructed, the program reads the packed compressed bytes one bit at a time. A zero bit means that the program moves to the left child of the tree, while a one bit means that it moves to the right child. Whenever a leaf node is reached, the corresponding character is recovered and the traversal starts again from the root of the tree.

The recovered characters are written into a new output file. Since Huffman coding is a lossless compression technique, the extracted file should contain exactly the same data as the original file. The program therefore performs a final verification by comparing the original file with the extracted file byte by byte. If both files are identical, the program reports that lossless verification was successful. This demonstrates that the compression process reduced or transformed the representation of the data without losing any of the original information.

The project demonstrates several important data structures. The map is used to maintain the relationship between characters and their frequencies. The priority queue is used as a minimum heap to repeatedly select the least frequent nodes during Huffman tree construction. The Huffman tree is a binary tree used to represent the variable length codes. Pointers are used to connect the nodes of the tree, and recursion is used while traversing the tree to generate codes and decode the compressed data. By combining these data structures, the project demonstrates how theoretical concepts from data structures can be applied to a practical file compression problem.

The complete compression process can therefore be summarized as reading the input file, calculating character frequencies, creating Huffman nodes, inserting the nodes into a minimum priority queue, constructing the Huffman binary tree, generating binary codes, encoding the original data, packing the encoded bits into bytes, and storing the result in a Huffman archive. The extraction process performs the reverse operation by reading the archive metadata, rebuilding the Huffman tree, decoding the compressed bits, reconstructing the original data, and verifying that the extracted file is identical to the original file. This makes the project a practical demonstration of Huffman coding, binary trees, priority queues, recursion, file handling, and lossless data compression.
