# File Archiver & Compressor

> A high-performance, lossless binary compression and decompression engine written in **C (C11)** utilizing dynamic Huffman coding, coupled with an interactive **HTML5/Flask** web GUI for real-time archiving and performance metrics.

---

## 📌 Overview

Traditional compression utilities often treat compression logic as an opaque black box. This project implements a fully transparent, bit-level lossless compression and archiving utility designed to demonstrate foundational **Data Structures and Algorithms (DSA)** in a real-world system.

The core engine is built in native standard C without external dependencies. It processes arbitrary binary files (uncompressed bitmaps, documents, audio, and raw text) using constant-memory buffered streams, an array-based min-heap priority queue, dynamic binary trees, and bitwise stream serializers. A lightweight local Python bridge connects the compiled C executable to a modern web-based graphical interface.

## ✨ Features

- **Binary-Safe Bit Streaming:** Operates on raw byte values ($0\text{–}255$), handling images, compiled binaries, and documents without character truncation or null-byte termination bugs.
- **Constant Memory Footprint:** Streams data in 64 KB blocks rather than loading full payloads into RAM, preventing out-of-memory errors on large files.
- **Original Filename & Extension Preservation:** Archives store original filenames and extensions inside metadata, automatically restoring the correct format on extraction.
- **Custom `.huff` Archive Specification:** Structured binary format storing frequency serialization tables and bitstream boundaries to reconstruct the tree accurately on any machine.
- **Dual Interfaces:** Full web-based GUI via browser plus direct CLI support for headless server environments or automated scripts.

## 📦 `.huff` Binary Archive Specification

Every `.huff` archive generated by the engine adheres to this compact binary structure:

| Field | Type / Size | Description |
|---|---|---|
| **Magic Number** | `char[4]` | Format identifier (`HUF2`) |
| **Filename Length** | `uint16_t` | Byte length of original filename |
| **Original Filename** | `char[N]` | Full filename including extension (e.g., `image.bmp`) |
| **Original File Size** | `uint64_t` | Uncompressed byte count of original source |
| **Unique Symbols ($K$)** | `uint16_t` | Distinct byte symbols present in file ($1\text{–}256$) |
| **Frequency Table** | $K \times (1 + 8)$ bytes | Symbol byte followed by its 64-bit frequency count |
| **Encoded Bit Count** | `uint64_t` | Total valid bits written in the encoded bitstream |
| **Bitstream Data** | Variable | Packed bits (MSB-first) ending with byte alignment |

---

## 🧠 Data Structures Implemented

1. **Min-Heap (Priority Queue):** Array-based binary heap with $O(\log K)$ insertions and extractions, used to iteratively combine the two least-frequent nodes during tree generation.
2. **Huffman Binary Tree:** Dynamically allocated binary tree constructed from frequency-weighted leaves. Left branch traversals assign bit `0`, while right branch traversals assign bit `1`.
3. **Bitwise Stream Buffer:** Internal 8-bit register that packs variable-length prefix codes and flushes complete bytes directly into the output stream.

## 🚀 Getting Started

### Prerequisites

- **GCC Compiler** (MinGW on Windows, or default GCC on Linux/macOS)
- **Python 3.8+** (for the Web GUI bridge)

### 1. Compile the C Engine

```bash
# Windows
gcc -O2 main.c -o FileArchiver.exe

# Linux / macOS
gcc -O2 main.c -o FileArchiver
```

### 2. Install Python Dependencies

```bash
pip install flask
```

### 3. Run the Web Application

```bash
python app.py
```

Open **`http://127.0.0.1:5000`** in your browser.

---

## 💻 Command-Line Usage

The engine can also be executed directly without launching the web GUI:

```bash
# Compress any file into a .huff archive
./FileArchiver -c input.bmp output.huff

# Extract a .huff archive (automatically restores original filename)
./FileArchiver -x output.huff

# Extract a .huff archive with a custom destination path
./FileArchiver -x output.huff custom_name.bmp
```

## 📊 Compression Performance & Entropy Analysis

Huffman coding is an **entropy-based statistical compression algorithm**. Its efficiency depends on the frequency distribution of symbols in the source payload:

| File Format | Typical Space Saved | Why / Behavior |
|---|---|---|
| **Raw Text / Source Code** (`.txt`, `.csv`, `.c`) | **40% – 60%** | Skewed symbol frequencies (vowels, spaces, keywords occur far more frequently than rare characters). |
| **Uncompressed Bitmaps** (`.bmp`, `.ppm`) | **30% – 65%** | Large repeating sequences of uniform background or palette pixel values. |
| **Uncompressed Audio** (`.wav` PCM) | **15% – 35%** | Predictable byte distributions in silent or harmonic sections. |
| **Pre-Compressed Files** (`.png`, `.jpg`, `.pdf`, `.zip`) | **~0% (or +0.05%)** | Already compressed with DEFLATE/LZ77 or DCT transforms. Byte entropy is near maximal ($256$ equally distributed symbols), leaving no redundancy for Huffman to reduce. Header overhead results in a slight size increase. |
